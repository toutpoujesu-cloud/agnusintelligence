Step 1 of 8 — Understand4 min

The prototype becomes real, running software.

Everything so far has produced documents and a clickable prototype. Now you hand that work to Claude Code — a different tool again — and it assembles the actual application. Your job is not to write the code. Your job is to make sure the handoff is complete, and to oversee the build.

The problem this phase solves: the design-to-code gap

"The handoff is where the designer's vision and the developer's implementation historically diverged. Designers handed over static mockups; developers interpreted them — often differently. The result: a 'lossy export' with pixel-perfect execution on the first screen, but when real components, edge cases, and responsive states were added, the design fell apart."

What you built in Claude Design isn't a picture Claude Code has to guess its way back into code from. It's machine-readable — Claude Code already knows which components to use, which styles to apply, which structure to respect.

Step 4 of 8 — Two Commands5 min

You type these into Claude Code — Claude does the rest

You are not writing scripts. These are single-line commands you type, that trigger Claude Code to do the real work of syncing and importing.

First: sync your design system in

/design-sync
"Use /design-sync to pull in your design system, so everything you build in Claude Code starts from your existing components. Claude builds with your real design system components, checks its own output against your design system, and makes corrections before you see them."

Then: send the whole project across

/design-handoff [project-name]
"Send the entire project to the coding tool with a single instruction. This creates the design bundle in your project repository, ready for Claude Code to implement."

You can also start entirely from the terminal — "Type '/design a few options for {feature}' in the terminal, and Claude generates multiple interface concepts as editable artboards, allowing developers to review and choose before implementation."

Step 5 of 8 — The Handoff Contract6 min

The most important safeguard in this whole phase

A mockup can look finished without being real. Claude Code needs to be told, explicitly, which parts of what it received are actual production material versus which parts are just illustrative sketches — otherwise it might ship a placeholder as if it were the real thing.

Explicit non-goals — real examples from the handoff template

This handoff is NOT asking Claude Code to:
  • Recreate generated prototypes pixel-perfectly unless a later task specifically asks for production UI implementation
  • Migrate seed React / JSX recreations into the production codebase
  • Adopt placeholder logo, wordmark, or icon assets from the seed
  • Claim the seed is canonical
  • Claim member surfaces are shipped if the seed depicts them as illustrative
"State every thing this handoff is not asking Claude Code to do. Be specific. Generic non-goals do not protect the truth boundary."

Every artifact carries one truth label

implemented / current UI repo-grounded public explainer repo-grounded architecture explainer illustrative direction future-state / roadmap historical do not use

If you can't tell which label applies to something Claude Design produced, that's a sign the handoff isn't ready yet — not something to guess your way past.

Step 6 of 8 — The Assembly Guide6 min

Six steps, from project setup to a finished, verified build

A
Set up the project

Clone or create the repo, copy the handoff bundle in, run /design-sync in Claude Code.

B
Generate the base structure

Run /design-handoff [project-name] — Claude Code reads the component structure and design tokens, and creates component files following the implementation rules.

C
Assemble the UI

Claude Code generates each UI component from the design system, organized per the architecture diagram. You review and iterate.

D
Implement the logic

Claude Code implements backend logic — API routes, database queries — and connects the UI to it.

E
Verify against the blueprint

You run the application and test it against the Phase 2 behavior specifications. Claude Code fixes any gaps found.

F
Finalize and document

You generate the final deliverable, Claude Code runs tests, and the Build Journal is completed.

What the actual verification checks for

CheckWhat you're confirming
VisualDoes the UI match the Claude Design prototype — colors, fonts, spacing consistent?
FunctionalDoes the workflow work as specified in Phase 2? Do edge cases behave as expected?
StructuralDoes the file system match Phase 3's structure? Is the code organized per the architecture?
Design systemDoes the assembly use the correct components? Are there deviations?

Step 8 of 8 — Practice7 min

Claude Design produced a set of screens showing a "member dashboard" feature that hasn't actually been built into the real product yet. What must the handoff documentation do with this?

ANothing — Claude Code will figure out on its own whether this is real or illustrative.
BLabel it explicitly as "illustrative direction" or "future-state / roadmap," and state as a non-goal that this handoff is not claiming the feature is shipped.
CDelete the screens entirely, since anything not yet built shouldn't appear in a handoff.
DRename the screens so they look identical to already-implemented ones.
EShip it directly to production without any label, since Claude Design already generated working code.

New scenario — no hints

You run /design-handoff and Claude Code assembles a working build. The visuals match the prototype exactly, but when you test the app against your Phase 2 behavior specifications, one workflow doesn't match what you originally designed. What is the correct next step, per the six-step assembly guide?

ATreat this as Step E — verify against the blueprint — and have Claude Code fix the gap before moving on to finalizing and documenting.
BIgnore it — visual accuracy is the only thing that matters in verification.
CRestart the entire assembly process from Step A.
DRewrite the Phase 2 behavior specification to match whatever Claude Code happened to build.
EThis can only be fixed by going back into Claude Design and regenerating the prototype.
