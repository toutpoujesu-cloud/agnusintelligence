From M36f — Test Before You Trust It
Why should the agent list test scenarios as a document before writing any test code?
Writing test code first tempts the agent to only test what's convenient, missing real gaps.
Documents are required by convention, with no practical benefit.
Test code cannot be written without a prior document.
From M36f — End-to-End Scenarios
What kind of scenario would an account-based app need that a simple to-do app wouldn't?
Sign up, log in, password reset, and related failure cases like repeated wrong-password attempts.
No difference — every app needs the exact same test scenarios.
Only visual/design scenarios, never functional ones.
From M36g — From Tested to Live
Why should the scenario list be re-run against the live URL, not just locally?
A missing environment variable or host misconfiguration can silently break something that passed locally.
It's a formality with no real risk of new failures.
Local and live environments are always identical.
