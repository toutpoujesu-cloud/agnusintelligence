AGNUS Academy Level 8 · Foundation L8-04 — Models vs. Frameworks
Step 1 of 4 — Understand4 min

A model is the brain. A framework is the nervous system that runs the loop from L8-01.

Claude, GPT, and Gemini are models — they reason and generate text. LangGraph, the Claude Agent SDK, and CrewAI are frameworks — they implement the Plan → Act → Observe loop, manage memory tiers, and route tool calls. Confusing the two leads to real, avoidable mistakes.

Why this matters

"Which AI should I use?" is often really two separate questions — which model, and which framework — being asked as if they were one. A team can pick an excellent model and still fail, because the framework running it doesn't handle memory or tool errors well; or vice versa.

Step 2 of 4 — See4 min

The stack — where each piece actually sits

Framework layer

Runs the Plan → Act → Observe loop, manages the three memory tiers from L8-03, routes tool calls, decides when to stop. Examples: LangGraph, Claude Agent SDK, OpenAI Agents SDK, CrewAI.

Model layer

Does the actual reasoning and text generation each time the framework calls it. Examples: Claude, GPT, Gemini. The model has no memory of its own between calls — the framework supplies that.

The framework calls the model repeatedly as part of running the loop — the model itself doesn't "remember" the previous iteration; the framework re-supplies whatever context (working, episodic, or semantic memory) it decides is relevant each time.

A common, avoidable mistake

Blaming "the AI" for a memory failure when the actual defect is in the framework's memory management — or blaming the framework when a reasoning error actually came from the model itself — wastes time fixing the wrong layer. The two failure sources look identical from the outside unless you know to check both.
