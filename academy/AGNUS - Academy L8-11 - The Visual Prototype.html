Step 3 of 8 — Step 1: Design System6 min

Before any screen exists, tell Claude what "on-brand" means

A design system is the set of colors, fonts, and reusable pieces your prototype will draw from. Without one, every new screen risks looking like a slightly different, generic product. With one, everything Claude builds automatically matches.

"One of the first steps when configuring your account will be to create a design system. Claude Design goes deep here: it accepts a link to your GitHub code repository, local file uploads, Figma references, and uploaded assets such as fonts or images."
What the design system doesWhy it matters
Automatically applies brand colors, typography, componentsEverything you create uses your established patterns, not generic AI defaults
Claude builds with real componentsClaude checks its own output against your design system and corrects itself before you see it
Larger teams get consistencyAn admin can approve one standard system and lock down edits

What to say to set it up

Based on the blueprint and file structure we've established, I need you to help me set up the design system in Claude Design. Generate a comprehensive design system that includes: Color palette with primary, secondary, and accent colors Typography system with headings, body, and UI text styles Component library for all UI elements Spacing and layout grid system Interactive states for all components Base this on the audience research we conducted in Phase 2 and the platform choices from Phase 3. Make it appropriate for a [describe audience] using a [describe platform] application.
Step 4 of 8 — Step 2: The Four-Part Prompt6 min

The gap between a beginner and a genuinely usable result is one thing: structure

"The gap between a beginner's first result and a genuinely usable one is almost always the difference between a one-line prompt and a properly structured brief."
ElementWhat to includeExample
GoalWhat this piece of output needs to accomplish"Create a customer support dashboard that lets agents view and respond to tickets"
AudienceWho's actually going to see it"For a B2B SaaS support team who handle 50+ tickets per day"
Key InformationThe specific content that has to be present"Show ticket status, priority, customer tier, and order history"
Layout StructureRoughly how it should be organized"Dashboard with metrics at top, tickets in a sortable table below, and detail panel on the right"

Proven prompt examples

"Create a dashboard showing monthly revenue with filters for region and product line" "Design a mobile app onboarding flow with 4 screens that walks users through our core features" "Build a landing page for our new API product with a hero section, code examples, and pricing" "Create a form for collecting customer feedback with conditional questions based on category"
"A good prompt includes the goal (what you're building), the layout (how things should be arranged), the content (what information to display), and the audience (who will use it). Claude will also ask clarifying questions if it needs more information."

Name your components — don't describe colors from scratch

Once a design system is in place, referencing its components by name inside a prompt — "use the primary button style from the design system" rather than "make the button blue" — produces noticeably more consistent results, since Claude Design is drawing on an actual, defined component rather than reinterpreting your intent from scratch each time.

Step 5 of 8 — Step 3: Refining5 min

The first few refinements matter most

"Refinement requests tend to produce their biggest improvements in the first handful of rounds, and pushing well past that point on the same piece of output tends to yield smaller and smaller gains for the same amount of prompting effort."

Don't expect the twentieth refinement pass to move the needle like the second one did. If you're stuck making tiny tweaks with no real improvement, that's often a sign to step back and reconsider the brief itself, not to keep nudging the same design.

ApproachWhen to useExample
ChatBroad changes that affect the whole design"Make the color scheme darker and more minimalist"
Inline CommentsSpecific element feedbackComment on a button: "This should be larger and more prominent"
Direct Canvas EditingPrecise adjustmentsMove elements, resize, change text

More chat refinement examples

"Make the color scheme darker and more minimalist" "Rearrange the dashboard so the metrics are in the top row and the chart is below" "Add a settings panel on the right side" "Show me 2–3 alternative layouts for this page"
Step 6 of 8 — Step 4: Handoff6 min

This is the moment the prototype becomes real software

When a design is ready, you hand it off to Claude Code — a different tool that turns the visual prototype into actual, running code. You will not be writing this handoff by hand.

"When a design is ready to become software, you can hand it off to Claude Code, which continues from your existing work instead of starting over from a screenshot."
"The handoff is where Claude Design distinguishes itself from traditional design tools. It produces what Anthropic calls a 'handoff bundle' that Claude Code can use to implement the design as functional software."

The prototype generated in Claude Design becomes a "handoff bundle" — a highly condensed instruction set passed directly to Claude Code, completing the transition from visual prototype to production code. "The operation closes the loop with Claude Code: at the end of the exploration phase, the user can send the entire project to the coding tool with a single instruction, skipping the step of manual rewriting by the developer."

Why this matters to you specifically

This is the reason the design phase and the coding phase are not two separate, disconnected efforts you have to reconcile by hand. What you build and refine visually here is what Claude Code will actually build from — not a picture Claude Code has to guess its way back into code from.

Step 7 of 8 — Step 5: Context & Testing6 min

More context in, better prototype out

"The more context you give Claude, the better your output will be. You can attach reference material at any point during a project."
Context typeWhat it doesExample use
Screenshots, Images, AssetsUpload existing designs, competitor products, wireframes, or visual inspiration"Make it look like this"
Codebases & Existing Design FilesLink a code repository so Claude understands your existing components and stylingMakes prototypes more production-ready from the start
Design SystemsOne or more from GitHub, design files, raw uploads, or local codebaseEnsures brand consistency
Voice InputTalk out your ideas instead of typingRapid idea capture

Give it something real to check itself against

Deliberately test your design system's limits: throw an unusual content type at it — a data-heavy dashboard, a long-form article layout, something you didn't include in your original setup — and see whether it holds up or starts improvising. That's the fastest way to find the gaps before a real project exposes them for you.
