Closing out Level 6: don't just pass the tests given to you — write your own.

Every module so far in this level tested you against a case someone else designed. The actual skill of building a guardrail is anticipating the cases that would break it before they happen in production.

Why this matters

A guardrail that's only ever been checked against the one example used to build it is largely untested. Writing your own test cases — including deliberately adversarial ones designed to slip past the rule — is what actually tells you whether a guardrail holds up, closing the loop from M36f's testing discipline back to the design work across this entire level.

04"Everyone knows this is the best option."Should flag — unverifiable opinion stated as fact

Why case 4 is the interesting one

Cases 1–3 test the obvious distinction the gate was built for. Case 4 is an adversarial test: it contains no number at all, so a naive gate built only to catch statistics (like the flawed one M40's Pass step described) would let it straight through — even though it's exactly the kind of confident, unverifiable claim the gate exists to catch. A good test suite deliberately hunts for gaps like this.
