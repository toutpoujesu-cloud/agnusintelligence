A model responds.
An agent acts.

That single word — acts — changes everything. When an AI can modify a file, send a message, or spend money, it has crossed from conversation into consequence. This module teaches you to see that line clearly.

6 steps ~18 min Prerequisite for all Level 2+ modules

Why this is the most important distinction in AI

Most people who work with AI tools — writing assistants, image generators, chatbots — are working with models. They ask, the model responds, and nothing happens in the world except a response appearing on a screen. The model is stateless, contained, and reversible. You don't like the response? Ignore it.

An agent is different. An agent is a model with tools — tools that reach outside the conversation and do things. It might read your calendar, update a spreadsheet, send an email, or submit a payment. Those actions have consequences that persist after the conversation ends. You can't ignore them.

Understanding this distinction isn't academic. It determines what governance you need, what oversight you apply, and what can go wrong if you treat an agent like a chatbot.

The stakes change when AI can act

A wrong prediction from a model is just a bad sentence — you see it, you discard it. A wrong action from an agent can delete a file that doesn't come back, send a message you can't unsend, or charge a card that takes days to reverse. The governance framework you build around any AI system must start from this reality.

Plain model
Predicts text
Turns input into output. Nothing else happens.
Receives a prompt, produces a response
No connection to external systems, files, or services
Output is text — nothing in the world changes
Stateless — no memory between conversations
Error = bad response. Ignore it and move on.
Agent
Predicts text + acts
A model with tools that reach into the real world.
Receives a task, uses tools to accomplish it
Connected to files, APIs, calendars, payment systems
Actions persist — the world is different after the agent runs
Can maintain memory and context across tasks
Error = real action. Cannot always be undone.

The same model can be both

This is where people get confused. GPT-4, Claude, Gemini — these are all models. But those same models can be deployed as agents when you give them tools. The model inside a customer service chatbot that only answers questions is a plain model. The same model configured to access your CRM, send emails, and update tickets is an agent. The difference is the tools, not the model.

Step 3 of 6Same question. Two very different systems.
4 min
The question
"Schedule a 30-minute meeting with the whole team for Thursday."
A
Plain model — what happens
The model generates a response: "Sure, here's a suggested calendar invite you could send to your team for Thursday at 10am: Subject: Team Meeting..."
Reality check
No meeting exists. No calendar was touched. No one was notified. The model produced text that describes a meeting. You still have to do the actual scheduling yourself.
B
Agent — what happens
The agent reads all team calendars, finds the first available Thursday slot where everyone is free, creates a calendar event, sends invites to every team member, and confirms the meeting in your calendar.
Reality check
A real meeting now exists. Real invites were sent. If the agent picked the wrong Thursday, or the wrong attendees, or the wrong duration — those are real consequences that now need to be corrected.
The principle: A model gave you a draft to act on. An agent acted on your behalf. Both can be based on the same underlying AI. The difference is what connected to the calendar API.

Three more examples — spot the difference

1

"Summarise my emails from today."

Model: Produces text describing what email summaries might look like. It hasn't read your emails.
Agent: Reads your actual inbox, returns real summaries of real emails that arrived today.

2

"What's the weather in Oslo right now?"

Model: Tells you what it knows from training data — which may be months old and is certainly not "right now."
Agent: Calls a real weather API, returns the actual current temperature in Oslo.

3

"Pay this invoice."

Model: Generates text: "Here's how you could initiate payment for this invoice..."
Agent: Submits an actual payment instruction to the bank API. Irreversible.

Step 4 of 6Why the distinction governs everything
3 min

You govern agents differently from models

When a model produces bad output, the governance response is: review the output and discard it. The damage is limited to what you act on manually.

When an agent performs a bad action, the governance response is: catch it before it acts, or undo what it did — neither of which is always possible. This is why the governance framework for agents is fundamentally different. You need permissions, approval gates, audit logs, and intervention controls. You need these because the consequences are real and sometimes irreversible.

Governing a model

• Review output before acting
• Fact-check claims
• Adjust your prompt if results are poor
• No permissions needed
• No audit trail required

Governing an agent

• Define what it can and cannot do (permissions)
• Set thresholds that require human approval
• Log every action for accountability
• Build intervention controls
• Plan for action reversal

The most common mistake: Treating an agent like a chatbot — deploying it without permissions, without approval gates, without logging — because the underlying model feels familiar. The model is familiar. The agent's capacity to act in the world is not.

A
Nothing has changed in terms of risk — the AI is still doing the same job, just more efficiently.
B
The risk has increased because newer AI models are less reliable than older ones.
