The memory problem in AI

By default, language models are stateless — each conversation starts fresh. The model has no idea what you discussed yesterday, what tasks your agent completed last week, or what your company's specific policies are. Every session is the first session.

This is fine for a chatbot that answers one-off questions. It is a serious limitation for agents that need to operate continuously, build on previous work, and maintain organisational context. Memory is what bridges the gap — but it comes with governance requirements of its own.

Step 2 of 6The four types of AI memory
5 min

Not all memory is the same

AI systems can have memory in four different ways. Each serves a different purpose, persists differently, and carries different governance implications. An agent you deploy may have one, several, or all four.

Type 1 — In-context
The conversation window
Everything in the current conversation: your messages, the agent's responses, tool call results. This is temporary — it disappears when the session ends. Most basic AI interactions run entirely on in-context memory.
Scope: this session only · Persistence: none
Type 2 — External storage
Databases and documents
Information the agent retrieves from external sources — databases, vector stores, document archives, previous task logs. This persists indefinitely. The agent reads it via tool calls. This is where organisational knowledge lives.
Scope: retrieved per query · Persistence: permanent
Type 3 — Semantic memory
Trained knowledge
What the underlying model learned during training. It knows about programming, history, law, science — but its knowledge has a cutoff date and no access to your organisation's specific information unless it was in the training data.
Scope: global knowledge · Persistence: fixed at training
Type 4 — Procedural memory
Instructions and fine-tuning
How the agent has been configured to behave — system prompts, instructions, fine-tuning. This is where your organisation's rules, tone, approval thresholds, and restrictions live. It shapes how the agent acts, not just what it knows.
Scope: this agent · Persistence: until reconfigured

Step 4 of 6Memory and governance
3 min

Memory changes the risk profile of an agent

An agent without external memory is contained — everything it knows came from the current session, and when the session ends, it's gone. An agent with persistent external memory is a different proposition: it accumulates information across interactions, can be influenced by what it learned previously, and may retain data that should have been deleted.

External memory creates data governance obligations

If your agent stores information about customers, employees, or partners in an external database, that data is subject to GDPR and data minimisation requirements. You must define what the agent retains, for how long, and who can access it.

Procedural memory can drift if it's not version-controlled

System prompts and configuration instructions are a form of memory. If they change without governance, the agent changes — quietly, and potentially without anyone noticing until the behaviour change has already caused problems.

Memory can be poisoned

If an agent's external memory store contains incorrect or malicious information, the agent will act on it. A customer service agent trained on fabricated complaint history, or a document agent pointing to outdated policies, will produce wrong results confidently.

Governance principle: Know what memory your agent has, where it's stored, how it's updated, and what it retains. Undocumented agent memory is a governance gap.

The customer is frustrated because they have to explain everything again. A colleague suggests "fixing the memory" by giving the agent a larger context window.

Is a larger context window the right solution? Which memory type is actually needed?
A
Yes — a larger context window will allow the agent to remember more previous conversations.
B
No. A larger context window only extends the memory within a single session — it ends when the session ends. What's needed is external storage: a CRM or interaction log that persists across sessions, which the agent can retrieve via a tool call at the start of each new conversation.
C
The problem is semantic memory — the model needs to be retrained on this customer's history.
D
The agent should not have memory of previous conversations — this is a privacy requirement.
