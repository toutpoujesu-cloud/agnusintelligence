From L8-01 — Anatomy of an AI Agent
What makes an AI agent different from a chat model answering a single question?
It uses a larger model with more parameters.
It runs a loop: it plans, takes real actions with tools, observes the result, and decides what to do next.
It always gives the correct answer on the first try.
From L8-03 — Agent Memory Architecture
Why does a long project need memory stored outside the conversation?
The conversation ends or runs out of room, so anything not written down is lost to the next session.
Models remember every past conversation automatically.
Memory outside the chat makes the model faster.
From L8-06 — MCP
What does MCP (Model Context Protocol) give an AI agent?
A new, more powerful language model.
A guarantee that its output is correct.
A standard way to connect to outside tools and data sources.
From L8-07 — The Execution Layer
Why use more than one AI platform on the same build, for example Claude Code to build and Codex to test?
Using more platforms always makes the app faster.
Each is stronger at different jobs, and a second independent system catches mistakes the first one missed.
One platform is enough; a second only adds cost.
From L8-08 — The Blueprint
What should the blueprint describe before any code is written?
The exact code for every file.
Only the colours and fonts.
The idea, the vision, who the users are, and how they will actually use the app.
From L8-09 — The Shaping
What is the risk of accepting the AI’s default design without direction?
You get a generic look that isn’t shaped to your users or your brand.
The app will fail to run.
There is no risk; the default is always best.
From L8-10 — The Structuring
Why set up the folder and file structure before the agent starts coding?
Folder structure only matters after launch.
It gives the agent a fixed map, so files land in the right place and the project doesn’t sprawl.
The agent will always pick the ideal structure on its own.
From L8-11 — The Visual Prototype
What is the difference between the visual prototype and the working build?
They are the same thing.
The prototype is the final product shipped to users.
The prototype shows how the app looks and flows; the build is the real, working code.
From L8-13 — The Governance
Why tell the agent to read The Protocol at the start of every session?
A new session may be a different agent that won’t say so; The Protocol is how it learns the rules, roadmap and history.
It makes the agent write code faster.
It is only needed the first time.
From L8-14 — The Verification
The agent says “the login feature is done.” What should you do?
Accept it and move on to the next feature.
Run the test scenarios yourself and ask for proof, such as a screenshot of the passing result.
Ask the agent if it is sure.
