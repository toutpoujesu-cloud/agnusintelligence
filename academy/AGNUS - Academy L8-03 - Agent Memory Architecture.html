AGNUS Academy Level 8 · Foundation L8-03 — Agent Memory Architecture
Step 1 of 4 — Understand4 min

M04 covered context vs. persistent memory. Real agents split persistent memory into three distinct tiers.

Not all persistent memory is the same kind of memory. A well-architected agent separates what it's doing right now from what it's learned across many tasks — and mixing those two up causes real, specific failures.

Why this matters

An agent that stores everything in one flat memory either forgets things that should have persisted, or drags irrelevant task-specific detail into contexts where it doesn't belong. The three-tier model exists specifically to prevent both failure modes.

Step 2 of 4 — See5 min

The three-tier memory model — click each to expand

Working memoryLives: one task
The current context window — everything relevant to the task in progress right now. This is what M04 called the context window. It disappears once the task ends, unless something in it gets explicitly written to a longer-lived tier.
Episodic memoryLives: across a session, or several related tasks
A record of specific past events — "the user rejected this exact proposal on Tuesday" — that stays relevant for the current project or engagement, but isn't necessarily useful forever. Think of it as a project's own history, distinct from either the immediate task or a timeless fact.
Semantic memoryLives: indefinitely, across all future tasks
General, durable knowledge that should apply to any future task — "this client's brand voice is always formal" or "this codebase always uses four-space indentation." This is the tier that should survive long after any specific episode is forgotten.

Write-back: how working memory becomes collective intelligence

Working memory
(this task only)
→
Something durable is noticed
→
Explicitly written to episodic or semantic memory
→
Available to every future task, not just this one

Nothing moves to a longer-lived tier automatically — an agent (or its designer) has to explicitly decide that a detail from the current task is worth keeping, and write it there. Without that deliberate write-back step, every lesson is relearned from zero next time.

This detail matters for the rest of this week's interactions, but isn't a permanent fact about the customer. Which tier, and why?

AEpisodic memory — a specific, time-bound event relevant to the current engagement, but not a durable, permanent fact.
BSemantic memory — because it should influence how the agent treats the customer indefinitely.
CWorking memory — because it only matters for the current phone call.
DIt doesn't need to be written anywhere, since the agent will naturally remember it.
EAll three tiers equally, since the detail could theoretically matter in any context.
