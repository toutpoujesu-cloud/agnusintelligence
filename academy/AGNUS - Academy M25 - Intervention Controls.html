AGNUS Academy Level 4 · Govern M25 — Intervention Controls
Step 1 of 4 — Understand3 min

An intervention control is a mechanism that lets a human stop, redirect, or override an agent mid-task — before the consequence lands.

Governance isn't only about what an agent is allowed to do. It's about your ability to change course after the agent has started. That ability is an intervention control, and it must be designed in — it doesn't appear by default.

Why this matters at Level 4

At Levels 1–3 you learned to read agent behaviour and catch drift. At Level 4, you design the governance structures that make catching drift possible at scale — and that give you somewhere to go when you catch it. An intervention control is the mechanism that bridges observation and action.

The three types of intervention control

Type 1
Pause gate
A defined point in the task where the agent stops and waits for human confirmation before continuing. Designed in advance. The agent knows it will pause; the human knows to expect a pause. Effective for high-stakes sequential tasks.
Type 2
Interrupt signal
A mechanism the operator can trigger at any point to halt an agent mid-execution. Effective when the pause gate wasn't triggered but the operator has observed a problem developing. Requires a kill switch or equivalent in the agent's execution layer.
Type 3
Override instruction
A higher-authority instruction that supersedes the agent's current task brief. The agent continues running but on new parameters. Effective when the task doesn't need to stop — it needs to be redirected. Only works if the agent is designed to accept mid-task overrides.
Step 2 of 4 — See3 min

Same problem, three different control choices

Scenario: A contract-review agent is processing a batch of 200 supplier agreements. Midway through, the legal team realises one of the review criteria is incorrect — contracts are being flagged for a clause that is actually required.

Pause gate — if a pause gate was built in after every 50 contracts, the operator can catch the error at the next gate before more incorrect flags accumulate. The agent stops; the operator corrects the criteria; the agent resumes correctly. But the first 50 are already flagged incorrectly.

Interrupt signal — the operator triggers an interrupt immediately on discovering the error. The agent halts mid-batch. The operator corrects the criteria and re-runs from the point of the error. Zero additional incorrect flags after the interrupt. But the operator needs to have the interrupt mechanism to hand and know how to use it.

Override instruction — the operator sends a corrected review criteria instruction to the running agent. The agent applies the new criteria from its current position forward, without stopping. No re-run needed. Only works if the agent was designed to accept mid-task instruction updates — many are not.
