An escalation path is
the route from stuck to resolved.

When an agent encounters a situation it cannot handle within its authority — an unresolvable conflict, a condition outside its scope, a risk it cannot assess — it needs a defined path to a human who can. Without that path, the agent either freezes or improvises. Neither is acceptable.

6 steps ~14 min Final Level 3 module

What escalation paths are

An escalation path is an explicit, named route from an agent's decision point to a human with the authority to resolve it. It answers: who does the agent contact, through what channel, with what information, and within what timeframe?

Escalation is not failure — it's designed behaviour for situations the agent correctly identifies as outside its authority. An agent that escalates appropriately is working exactly as it should.

Unresolvable instruction conflict
The priority hierarchy (M20) doesn't resolve the conflict. Two Level 2 instructions contradict each other. The agent cannot determine which takes precedence without human input.
2
Action outside authority
The correct action requires authority the agent doesn't have — a payment above its threshold, a legal judgment it cannot make, a data access its scope doesn't permit.
3
Ambiguous condition not covered by fallbacks
The situation doesn't match any condition the brief covers, and the fallback says "escalate if uncertain." The agent has correctly identified that it doesn't have enough information to act.
4
High-risk signal detected
The agent detects a pattern that suggests something is wrong — duplicate invoice, unusual amount, first transaction with unknown supplier, sensitive data in unexpected context.
5
Retry limit reached
A tool has failed beyond the retry limit. The task cannot continue without human intervention to diagnose and resolve the underlying issue.
Next: anatomy of an escalation path
Step 3 of 6Anatomy of an escalation path
4 min
Escalation path — invoice with no PO match
1
Trigger
Invoice INV-2026-0448 — no matching PO found. Business rule: hold and escalate. Do not proceed to payment.
2
Stop action
Agent halts invoice processing. Marks the invoice status as "Pending escalation — no PO match." No further action on this invoice until resolution.
3
Escalation target
Accounts Payable team lead (ap-lead@nordvik.no). This is the defined human with authority to: (a) confirm the PO exists but is mislabelled, (b) create the PO retroactively, or (c) reject the invoice.
4
Escalation package
Agent sends: invoice ID, supplier, amount, date, reason for escalation ("No matching PO found — PO-matching returned null"), and the three resolution options.
Critical: the package must include the information the human needs to make the decision — not just "there is a problem."
5
Timeout behaviour
If no response within 4 hours during business hours: re-escalate to finance manager. If after-hours: hold until next business day, then escalate at opening.
6
Log
All escalation actions logged: trigger, target, package sent, timestamp, response received.
Next: broken escalation paths
Step 4 of 6What breaks an escalation path
3 min
Broken path 1
No defined target. The brief says "escalate to the relevant person." There is no named role, team, or contact. The agent cannot escalate — it has nowhere to go.
Fix 1
Name the specific role: "Escalate to the AP team lead at ap-lead@nordvik.no. If unavailable, escalate to the finance manager at finance-manager@nordvik.no."
Broken path 2
Escalation package is empty. The agent sends "Invoice INV-448 needs attention" with no context, no reason, no data. The human has to re-do the investigation from scratch.
Fix 2
Specify what must be in the package: "Include invoice ID, supplier, amount, reason for escalation, the data the agent found, and the available resolution options."
Broken path 3
No timeout behaviour. The agent waits indefinitely for a response that never comes. The invoice is stuck forever with no owner.
Fix 3
Define time behaviour: "If no response within 4 hours during business hours, escalate to the finance manager. Log the re-escalation."
Broken path 4
Escalation is never triggered. The brief defines an escalation path but no trigger conditions. The agent never knows when to use it.
Fix 4
Define exact trigger conditions: "Escalate when: (a) no PO match found, (b) amount exceeds €500, (c) duplicate detected, (d) retry limit reached."
A complete escalation path has five components: trigger condition, stop action, named target, complete package, and timeout behaviour. Missing any one makes the path unreliable.

A customer service agent's brief contains: "If a customer complaint cannot be resolved automatically, escalate it." Three weeks after deployment, the customer service manager discovers that the agent has been sending escalated complaints to a general inbox (info@company.no) that nobody monitors regularly, with only the message "Escalated complaint — please review."

Which two components of the escalation path were missing?
A
Trigger condition and timeout behaviour.
B
Named target and complete package. The brief said "escalate" without naming a specific monitored contact, so the agent used a general inbox. The package said only "please review" with no complaint detail, customer context, or resolution options — making it useless even if someone had seen it.
C
Stop action and logging.

Step 6 of 6Pass — hidden test
3 min

A colleague argues: "Escalation is a sign of poor agent design — a well-designed agent should be able to handle every situation autonomously." An experienced operator disagrees: "Escalation is built-in governance, not a design failure."

Who is right, and what is the key insight?
A
The colleague is right — escalation should be eliminated through better agent design.
B
The operator is right. Escalation is designed behaviour for situations that are correctly outside the agent's authority — legal judgments, authority it doesn't have, unresolvable ambiguity. An agent that escalates appropriately is not failing; it is correctly recognising the boundary of its authority and handing to the right human. An agent that never escalates is either operating in a perfectly bounded environment (rare) or improvising in situations where it should be escalating (dangerous).
C
Both have valid points — the goal is to minimise escalation as much as possible while keeping it as a fallback.
