Agentic AI Risk: The Capability-Control Gap

The risk profile of agentic AI is qualitatively different from AI systems that produce outputs for human review. When AI can act — not just advise — the consequences of misalignment, error, and misuse are immediate and potentially irreversible. This article maps the risk landscape for agentic AI systems: the capability-control gap, the six primary risk categories, and the controls that close them.

Contents

    The capability-control gap

    The capability-control gap is the central risk in agentic AI: as agent capabilities increase — more tools, broader access, longer planning horizons — the difficulty of maintaining effective human control increases faster than the capability does. An agent that can send emails, browse the web, and execute code is not three times harder to control than an agent that can only send emails. The interaction between capabilities creates emergent possibilities that no individual capability assessment would predict.

    This gap is not a temporary problem that will be solved by better AI models. A more capable agent is, by definition, an agent that can do more — which means more potential outcomes, more potential failures, and more potential misuse. The governance response is not to reduce capability but to design control architectures that grow with capability rather than falling behind it.

    The six primary risk categories

    High — Action risk
    Irreversible real-world actions
    An agent with external action capabilities can send emails that cannot be unsent, execute financial transactions that cannot be reversed, delete files that cannot be recovered, and send API calls that trigger downstream processes. The irreversibility of many real-world actions means that errors cannot be corrected after the fact — they can only be prevented before the fact or mitigated afterwards.
    High — Scope risk
    Scope expansion and task drift
    Agents optimising for their assigned goal may pursue that goal through means the deploying organisation did not intend and would not approve if asked. A research agent told to "find all relevant information" may access internal documents it should not see. A scheduling agent told to "clear the calendar" may cancel appointments that the human would have kept. Scope creep is not malicious — it is the natural result of goal-directed behaviour without clear boundary conditions.
    High — Injection risk
    Prompt injection via environmental inputs
    Agents that process external content — web pages, documents, emails, API responses — are vulnerable to indirect prompt injection: malicious instructions embedded in environmental content that cause the agent to change its behaviour. An agent browsing the web may encounter a page that instructs it to exfiltrate data or take an action unrelated to its task. OWASP ranks this as the top security risk for LLM applications.
    Medium — Accountability risk
    Attribution failure in multi-step tasks
    When a harmful outcome results from a sequence of agent decisions — each individually reasonable — attributing responsibility for the outcome is difficult. The legal and regulatory accountability frameworks for agentic AI are immature. Deploying organisations bear responsibility for foreseeable outcomes from their deployed agents, but the standard of foreseeability for novel agentic behaviours is not yet settled.
    Medium — Memory risk
    Persistent state and unintended learning
    Agents with persistent memory can carry errors, biases, or compromised states across sessions. A prompt injection attack in one session may persist in the agent's memory and affect its behaviour in subsequent sessions. Clearing agent memory between sessions is a governance control, not a technical default — many agent frameworks retain state unless explicitly instructed not to.
    Medium — Overreliance risk
    Automation bias and uncritical acceptance
    Users and organisations that rely on agentic AI for consequential tasks tend, over time, to accept agent outputs with decreasing critical scrutiny. This automation bias creates a risk that errors compound — not because the agent is failing more often, but because the human review that would catch failures is becoming less rigorous. Governance design must maintain human review quality, not just human review presence.

    Controls that close the gap

    Capability minimisation

    The principle of least privilege, applied to AI agents: each agent should have access only to the tools, data, and external systems required to complete its specific task. An agent that needs to read emails to complete a task should not have write access to the email system. An agent that needs to search the web should not have access to internal file systems. Capability minimisation is the most effective single control for reducing action risk and injection risk.

    Sandboxed execution environments

    Consequential agent actions should be executed in a sandboxed environment before they take real-world effect. This is especially important for code execution (where an agent-generated script can be run in an isolated environment before being applied), file operations (where changes can be staged before commit), and external communications (where outbound messages can be queued for review before sending).

    Human-in-the-loop at consequence boundaries

    Human approval should be required at the points where an agent crosses a consequence boundary — the moment it is about to take an irreversible action, contact an external party, or execute a high-value transaction. This is not the same as requiring human review of every agent decision — that would eliminate the efficiency value of the agent entirely. It is targeted oversight at the moments where the cost of error is highest.

    Anomaly detection and kill switches

    Every deployed agentic system should have a defined kill switch — a mechanism for immediately halting agent execution, preserving state, and escalating to human review. The kill switch should be reachable at all times, including when the agent is executing long-running tasks. Anomaly detection — automated monitoring for agent behaviour that deviates from baseline patterns — should trigger the kill switch or a human notification automatically, without requiring a human to be watching in real time.
