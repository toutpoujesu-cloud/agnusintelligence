What AGNUS is — the blueprint

AGNUS is an AI governance intelligence platform. Its purpose is to be the most trusted, most source-grounded resource for professionals who need to understand, comply with, and act on AI regulation — and for organisations deploying AI who need governance frameworks that actually work.

The insight behind AGNUS is that the AI ecosystem has two problems running in parallel. The first: there is too much noise and not enough primary-source clarity on what AI laws actually say. The second: there is no practical layer between "read the regulation" and "build a compliant system." AGNUS bridges both gaps.

◆

The positioning: AGNUS is not a tool review site. It is not a blog. It is not a consultancy. It is a structured intelligence platform — grounded in primary law, structured by pillar, updated by jurisdiction, and taught systematically. Bloomberg for AI governance.

The three commitments

  1. Primary sources only. Every factual claim links to the article, section, and paragraph of the originating law or standard. No invented summaries.
  2. Structure before volume. 100 articles organised into 6 pillars with cross-links beats 1,000 unconnected posts.
  3. Practice, not just theory. The Practice section provides usable tools. The Academy provides tested knowledge. Both are grounded in the same sources as the Research.

Data layer — contracts and migration

agnus-research-data.js — the JS data layer

The JS data layer is the bridge between the static HTML frontend and the future API backend. It exposes window.AR — a namespace that components call to get articles and sources.

// Current: synchronous JS object window.AR = (function() { const ARTICLES = [ { article_id: 'AR-000010', ... }, ... ]; const SOURCES = [ { source_id: 'SRC-0001', ... }, ... ]; return { ARTICLES, SOURCES, byArticleId: (id) => ARTICLES.find(a => a.article_id === id), byPillar: (p) => ARTICLES.filter(a => a.pillar === p), }; })(); // Future: async API wrapper — same interface, no template changes needed window.AR = { _cache: { articles: null, sources: null }, _load: async function() { const [articles, sources] = await Promise.all([ fetch('/api/articles').then(r => r.json()), fetch('/api/sources').then(r => r.json()), ]); this._cache = { articles, sources }; }, byArticleId: (id) => AR._cache.articles?.find(a => a.article_id === id), byPillar: (p) => AR._cache.articles?.filter(a => a.pillar === p), }; await AR._load(); // call once on page load

Article data contract

{ article_id: 'AR-000010', // unique ID, format: AR-NNNNNN source_id: 'SRC-0001', // primary source reference title: 'EU AI Act Explained', pillar: 'EU AI Act', // controlled: EU AI Act | AI Governance | AI Audit | Standards | AI Agents | AI Security | Intelligence jurisdiction: 'EU', // controlled: EU | UK | USA | Norway | Japan | Singapore | South Korea | Italy | China | Canada | Global published: '2026-08-22', // ISO date reading_time: 15, // minutes premium: false, // gating flag file: 'AGNUS - Research Article - AI Act Explained.html' }

Source data contract

{ source_id: 'SRC-0001', title: 'EU AI Act (Regulation 2024/1689)', issuing_organization: 'European Parliament and Council of the EU', url: 'https://eur-lex.europa.eu/...', date_published: '2024-07-12', verified: true, authority_type: 'primary' // primary | standard | academic | supporting }

End-to-end workflows

Workflow 1: Intelligence → Article (daily)

1

Agent runs daily scan

Intelligence agent checks 11 jurisdiction sources. Produces AGNUS-Daily-YYYY-MM-DD/manifest.json + per-jurisdiction intelligence-log-*.json. Flags findings with materiality: high/medium/low.

2

Research handoff generated

For each high/medium finding, agent produces research/[jurisdiction]/research-handoff-*.json with: title, question, verified_facts[], editorial_notes[], provisional_source. This is the article brief.

3

Claude Code picks up handoff

Watch handoffs/ folder. For each new research-handoff-*.json: extract title, verified_facts, source URL. Assign next AR-ID and SRC-ID from the data layer.

4

Article built from template

Use TEMPLATE - Research Article.html as base. Inject: title, deck, article body (from verified_facts), source block (from source), cross-links (from AR.byPillar). Save as AGNUS - Research Article - [Title].html.

5

Data layer updated

Add new article record to agnus-research-data.js ARTICLES array. Add source record to SOURCES array. Commit both files.

6

Deployed

Push to production. Article appears in Research hub, pillar filter, related articles sidebar, and daily intelligence feed.

Workflow 2: Learner through Academy

1

Learner arrives at AGNUS - Academy.html

Sees 7 path cards (Beginner to Enterprise). All cards link to academy/AGNUS - Academy App.html.

2

Academy App loads

Renders 7 levels, 52 modules. Auth check: free tier sees L1–L3, premium sees all. "Begin Level 1" button → location.href = 'AGNUS - Academy M01 - What is an AI Agent.html'.

3

Module completes

Each module has a hidden pass test. On pass: write completion to localStorage['agnus_progress'] as {'M01': true, 'M02': true, ...}. Academy App reads this on load to show progress badges.

4

Track B unlocks

After L1+L2 complete (M01–M14), Track B simulations unlock. Auth check: premium required. B01–B05 are standalone HTML files in academy/.

5

Certificate issued

On Track B B05 completion: generate competency certificate (PDF or page). Store in user profile. Credential ID format: AGNUS-B05-[timestamp36].

Design system tokens

All tokens are defined in AGNUS - Home.html :root {} and mirrored in agnus.css. Always reference tokens — never hardcode hex values in templates.

/* Core palette */ --char: #1C1B19; /* near-black — headings, logo, featured backgrounds */ --bg: #F8F7F4; /* warm white — page background */ --paper: #FCFBF8; /* off-white — card backgrounds */ --paper-warm: #F3F1EC; /* warm — sidebar, callout backgrounds */ --ink: #1D1D1F; /* body text */ --ink-soft: #6E6B66; /* secondary text */ --ink-mute: #908D86; /* metadata, captions */ /* Gold — used sparingly, only for accents and CTAs */ --gold: #B28A42; /* medium gold */ --gold-deep: #8F6E32; /* dark gold — links, accents */ --gold-light: #E7D6AE; /* pale gold — on dark backgrounds */ /* Typography */ --font-sans: "Manrope"; /* headings and UI */ --font-mono: "IBM Plex Mono";/* IDs, metadata, labels */ --font-serif: "Newsreader"; /* article body, italic accents */

Backend build — what needs to be built

Priority 1 — Required for launch

1

User authentication

Email + password auth. Two tiers: Free (access to free tools + L1–L3 Academy) and Premium (all tools + full Academy + Track B). Use NextAuth, Supabase Auth, or Clerk. Store tier in JWT. Add auth check to Academy App and Practice page.

2

Payment (premium subscriptions)

Stripe for subscription billing. Monthly and annual plans. Webhook to update user tier on payment. Connect to auth tier check.

3

Static file hosting

All HTML/CSS/JS at root, academy/, tandem/ must be served as static files. Vercel, Netlify, or Cloudflare Pages. No framework needed for the frontend — it is plain HTML.

4

agnus-research-data.js load order

Ensure all article pages load scripts in the correct order: agnus-research-data.js → agnus-research-components.js → agnus-research-components2.js. Currently correct in all pages — verify on deploy.

Priority 2 — Post-launch week 1

5

Search

Algolia or Typesense index over article titles, bodies, pillar, jurisdiction. Add search input to Explore page. Surface results with pillar filters.

6

Academy progress persistence

Write module completion to user profile (not just localStorage). API: POST /api/progress with {moduleId, completed: true, score}. Academy App reads from API on load (fall back to localStorage for guests).

7

Intelligence agent connection

Set up watcher on handoffs/ folder (or S3 bucket). When new research-handoff-*.json appears, trigger article build pipeline. See Workflow 1 above.

PDF export for Practice tools
